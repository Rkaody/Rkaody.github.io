## 연구 대상: PromptLock

**PromptLock**은 LLM을 단순한 도구가 아니라 **공격 로직의 의사결정 주체**로 사용하는 개념 증명(PoC) 랜섬웨어다. Go 언어로 작성된 단일 바이너리 형태로 배포됐으며, 공개된 소스코드가 없어 바이너리 역공학이 필요했다.

---

## 분석 방법

**Ghidra**로 Go 바이너리를 역공학했다.

- 분석 함수 수: **19개**
- 복원된 프롬프트: **11개 (총 9,701 바이트)**
- 프롬프트 위치: `.rodata` 섹션 (읽기 전용 데이터 영역)

Go 바이너리는 심볼 정보가 비교적 잘 남아있어 함수 경계 복원이 가능했다. 각 함수의 역할을 추적해 전체 실행 흐름을 재구성했다.

---

## 5단계 킬체인

```
1. 정찰 (Reconnaissance)
   └─ 시스템 정보 수집 (OS, 파일시스템, 실행 중인 프로세스 등)

2. 랜섬 대상 선정
   └─ LLM이 수집된 정보를 바탕으로 암호화할 파일 목록 판단

3. 암호화 코드 생성
   └─ LLM이 Lua 스크립트를 동적으로 작성

4. 인메모리 실행
   └─ 생성된 Lua 스크립트를 디스크에 저장하지 않고 메모리에서 직접 실행

5. 자기검증 (Self-verification)
   └─ LLM이 실행 결과를 확인, 실패 시 코드 수정 후 재시도
```

---

## 주요 보안 특성

### 인메모리 Lua 실행 (Anti-forensics)

생성된 암호화 코드를 파일시스템에 저장하지 않고 메모리에서 직접 실행한다. 실행 후에는 증거가 남지 않아 포렌식을 어렵게 만든다.

### LLM 자기검증 루프

암호화가 실패하면 LLM이 오류 메시지를 분석하고 코드를 수정해 재시도한다. 단순한 스크립트 실행기가 아니라 **스스로 디버깅하는 구조**다.

### 동적 코드 생성

최종 페이로드(Lua 스크립트)가 실행 시점에 LLM에 의해 생성된다. 정적 분석만으로는 실제 암호화 코드를 미리 파악할 수 없다.

### 복원된 프롬프트 구조

`.rodata`에서 복원한 11개 프롬프트는 각 단계의 역할을 LLM에게 지시하는 내용이다. 프롬프트가 바이너리에 하드코딩되어 있어 완전한 역공학이 가능했다.

## 기존 보안 도구에 대한 함의

| 보안 기법 | PromptLock에 대한 한계 |
|----------|----------------------|
| 정적 분석 | 최종 페이로드가 동적 생성됨 → 미리 파악 불가 |
| 시그니처 기반 탐지 | 매번 다른 Lua 코드 생성 → 시그니처 무효화 |
| 파일 기반 포렌식 | 인메모리 실행으로 파일 흔적 없음 |
| 행위 기반 탐지 | 정상 LLM API 호출과 구분이 어려움 |

## 의미

LLM이 멀웨어의 **오케스트레이터**로 사용된 최초 사례 중 하나다. 기존 정적 탐지 중심의 보안 도구가 이런 유형의 공격에 얼마나 취약한지를 실증했다.

LLM이 범용화될수록 이런 형태의 공격 시도가 늘어날 것이다. LLM API 사용 패턴 모니터링, 메모리 실행 탐지, LLM 출력 샌드박싱 등 새로운 방어 전략이 필요하다.
